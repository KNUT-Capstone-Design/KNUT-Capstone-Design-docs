# UI 설계서

- **문서 버전:** v1.0
- **배포일:** 2026-10-17
- **문서 상태:** 정식 배포 · 개발 기준선
- **작성일:** 2026-10-12
- **범위:** MVP 웹 화면 및 2차 회원·기관 UI 확장 계획
- **관련 문서:** [기능 명세](01_Feature_Specification.md), [사용자 흐름](02_User_Flow.md), [API 명세](05_API_Specification.md), [DB 설계](04_Database_Design.md)

> 문서 v1.0은 개발·검증 기준의 정식 배포 버전이다. 서비스 배포나 테스트 완료를 뜻하지 않는다. 문서별 기준과 변경 관리는 [문서 안내](../README.md)를 따른다.

## 1. 목적

URL·문자·QR 검사, 공통 결과, 예방 교육과 퀴즈 화면을 Frontend에서 구현할 수 있는 수준으로 정의한다. 화면 배치뿐 아니라 API 상태, 오류 복구, 반응형 동작, 접근성과 사용자 문구를 포함한다.

시각 디자인의 실제 색상·로고·일러스트는 팀 검토 후 조정할 수 있다. 화면 ID, 입력 제한, 상태 처리와 안전 표시 원칙은 구현 기준으로 사용한다.

## 2. UX 원칙

- 기본 검사와 공개 교육은 회원가입 없이 이용한다.
- 개인화와 기관 기능은 2차 로그인 영역으로 분리하고 공개 검사 진입을 방해하지 않는다.
- 제출한 자료의 처리 방식과 분석 범위를 검사 전에 설명한다.
- 색상만으로 상태를 구분하지 않고 아이콘·등급명·문구를 함께 사용한다.
- 의심 URL을 클릭 가능한 링크나 자동 미리보기로 만들지 않는다.
- 점수보다 분석 제한과 사용자가 해야 할 행동을 우선한다.
- 안전은 보증이 아니라 현재 검사 범위의 결과임을 알린다.
- 오류가 발생하면 입력을 유지하고 수정·재시도 방법을 같은 화면에 제공한다.
- 영문 enum과 내부 오류 코드를 사용자에게 그대로 노출하지 않는다.

## 3. 경로와 상태 보관

~~~text
/
├─ /analyze/url
├─ /analyze/message
├─ /analyze/qr
├─ /analyze/result
├─ /education
│  └─ /education/{id}
├─ /quiz
└─ /quiz/result
~~~

검사 결과와 퀴즈 진행 데이터는 브라우저 메모리에서 관리한다. 검사 원문·결과·답안을 URL이나 브라우저 영구 저장소에 넣지 않는다.

결과 데이터 없이 결과 경로에 직접 접근하거나 새로고침하면 검사 선택 안내를 표시한다. 퀴즈 결과 데이터가 없으면 퀴즈 시작 화면으로 안내한다. 교육 목록의 공개 필터와 페이지는 URL 쿼리에 저장할 수 있다.

## 4. 반응형 레이아웃

- 모바일: 360~767px
- 태블릿: 768~1023px
- 데스크톱: 1024px 이상
- 최소 지원 폭: 360px
- 주요 콘텐츠 최대 폭: 1,120px
- 검사 입력·교육 상세 최대 폭: 800px
- 검사 결과 최대 폭: 960px
- 모바일 좌우 여백: 20px
- 태블릿 이상 좌우 여백: 32px
- 버튼과 입력 최소 높이: 44px

모바일에서는 카드를 한 열로, 태블릿 이상에서는 내용에 따라 두세 열로 배치한다. 긴 URL과 추출 텍스트는 컨테이너 안에서 줄바꿈한다.

## 6. 공통 구조

### 6.1 Header와 Footer

데스크톱 Header:

~~~text
[서비스명]   URL 검사  문자 검사  QR 검사  교육  퀴즈
~~~

모바일 Header:

~~~text
[서비스명]                               [메뉴]
~~~

- 서비스명은 메인으로 이동한다.
- 현재 메뉴에는 시각 표시와 aria-current를 적용한다.
- 모바일 메뉴는 키보드와 Escape로 조작할 수 있어야 한다.
- MVP에는 로그인 메뉴를 만들지 않는다. 2차에서는 계정 메뉴를 추가하되 검사 버튼보다 강조하지 않는다.
- Footer에는 참고용 결과, 데이터 처리 원칙과 프로젝트 정보를 간단히 표시한다.
- 실제 주소가 확정되지 않은 신고 기관 링크는 미리 만들지 않는다.

## 7. S-001 메인 화면

- **경로:** /
- **목표:** 서비스 목적과 세 검사 유형을 이해하고 바로 시작한다.

~~~text
┌──────────────────────────────────────────────┐
│ 의심스러운 링크, 열기 전에 확인하세요          │
│ URL·문자·QR 코드의 위험 요소와 대응 방법을     │
│ 확인할 수 있습니다.                           │
│                                              │
│ [URL 검사] [문자 검사] [QR 검사]              │
└──────────────────────────────────────────────┘

[URL 검사 카드] [문자 검사 카드] [QR 검사 카드]

[스미싱 사례로 배우기]       [예방 퀴즈 풀기]

※ 결과는 참고 정보이며 안전을 보장하지 않습니다.
~~~

Hero 버튼과 기능 카드는 같은 경로로 이동한다. 모바일에서는 카드 한 열, 태블릿 이상에서는 세 열이다. 기술 스택, 회원 기능, 조작 이미지 판별 등 MVP 밖 기능은 첫 화면에 노출하지 않는다.

## 8. 검사 화면 공통

검사 유형 전환 탭, 화면 제목, 분석 범위 설명, 입력 카드, 검사 버튼, 개인정보·저장 정책 순으로 배치한다.

작성 중인 입력이 없으면 검사 유형을 바로 전환한다. 입력이 있으면 “작성 중인 내용이 사라집니다” 확인 후 이동한다. 검사 버튼은 유효한 입력이 있고 분석 중이 아닐 때 활성화한다.

제출 후 입력을 유지한 채 로딩 상태를 표시한다. 클라이언트 검증을 통과해도 서버 오류를 최종 기준으로 처리한다. FE 30초 제한에 도달하면 요청을 중단하고 입력을 유지한다.

## 9. S-101 URL 검사

- **경로:** /analyze/url
- **API:** POST /api/v1/analysis/url
- **입력:** HTTP(S) 절대 URL, 최대 2,048 code point

~~~text
URL 검사

의심스러운 주소를 입력하세요.
웹페이지에 직접 접속하지 않고 주소 문자열을 분석합니다.

URL
┌─────────────────────────────────────────────┐
│ https://example.com                         │
└─────────────────────────────────────────────┘
오류 문구

[URL 검사하기]

※ URL 원문과 결과는 DB에 저장하지 않습니다.
~~~

- label을 placeholder로 대체하지 않는다.
- 앞뒤 공백은 제출 시 제거하고 프로토콜은 자동 추가하지 않는다.
- 빈 값, 길이 초과, HTTP(S)가 아닌 주소는 제출 전에 안내한다.
- 서버의 422 오류도 같은 입력 영역에 표시한다.
- 오류 필드와 문구를 aria-describedby로 연결한다.

문구:

- 빈 값: “검사할 URL을 입력하세요.”
- 형식 오류: “http:// 또는 https://로 시작하는 올바른 URL을 입력하세요.”
- 길이 초과: “URL은 최대 2,048자까지 입력할 수 있습니다.”

## 10. S-102 문자 검사

- **경로:** /analyze/message
- **API:** POST /api/v1/analysis/message
- **입력:** 최대 5,000 Unicode code point

~~~text
문자 검사

받은 문자나 메신저 내용을 붙여넣으세요.
개인정보는 지우고 검사하는 것을 권장합니다.

┌─────────────────────────────────────────────┐
│ [Web발신] 고객님의 배송 주소를 확인하세요.    │
│                                      36/5000│
└─────────────────────────────────────────────┘
오류 문구

[문자 검사하기]
~~~

- API와 같은 code point 기준으로 글자 수를 계산한다.
- 초과 시 카운터와 입력 테두리를 오류로 표시하고 버튼을 비활성화한다.
- URL 분석 여부를 FE에서 예측하지 않고 응답의 url_results를 사용한다.
- matched_spans는 HTML 삽입 없이 안전한 텍스트 노드로 나눠 강조한다.
- 강조에는 색상 외에 밑줄·규칙 라벨을 함께 사용한다.
- URL 5개 초과와 일부 URL 실패를 결과 상단에서 안내한다.
- 이름·전화번호·계좌번호·인증번호 제거 안내를 입력 전에 보여준다.

## 11. S-103 QR 검사

- **경로:** /analyze/qr
- **API:** POST /api/v1/analysis/qr
- **입력:** PNG/JPG/JPEG 한 개, 최대 10,000,000 bytes, 각 변 4,096px 이하

빈 상태:

~~~text
┌─────────────────────────────────────────────┐
│ QR 이미지를 끌어놓거나 파일을 선택하세요      │
│                 [파일 선택]                 │
│ PNG · JPG · JPEG / 최대 10MB / 최대 4096px │
└─────────────────────────────────────────────┘
※ 정상 분석 후 즉시, 실패 시 최대 10분 이내 정리합니다.
~~~

미리보기:

~~~text
[이미지 미리보기]  image.jpg
                   2.4MB · 1080×1080
                   [다른 이미지] [제거]

[QR 검사하기]
~~~

- 파일 입력은 키보드와 스크린리더로 접근 가능해야 한다.
- FE는 MIME·용량·해상도를 1차 확인하고 서버 검증을 최종 기준으로 사용한다.
- 미리보기 object URL은 파일 변경·화면 이탈 시 해제한다.
- 여러 파일을 드롭하면 첫 파일을 임의 선택하지 않고 한 개만 올리도록 안내한다.
- 업로드 중 파일 변경·제거·중복 제출을 비활성화한다.
- 미인식·복수 QR 오류에서도 미리보기와 재시도 동작을 유지한다.

## 12. S-104 분석 진행 상태

별도 페이지를 만들지 않고 입력 카드 안에서 표시한다.

~~~text
[로딩 아이콘] 위험 요소를 분석하고 있습니다.
입력 형식과 탐지 규칙을 확인하는 중입니다.
~~~

실제 진행률을 알 수 없으므로 퍼센트는 표시하지 않는다. 10초 후 “평소보다 시간이 걸리고 있습니다”를 추가한다. aria-live 영역으로 상태를 알리고 중복 제출을 막는다. 이동은 허용하되 QR 파일 삭제 완료를 FE에서 단정하지 않는다.

## 13. S-105 공통 결과

- **경로:** /analyze/result
- **상태:** completed, partial, not_applicable, 데이터 없음

표시 순서:

1. 부분 결과·분석 제한 경고
2. 위험 등급·점수·요약 또는 분석 대상 아님
3. 치명 규칙 상향 안내
4. 판단 근거
5. 유형별 세부 결과
6. 권장 행동
7. 검사 정보와 참고 안내
8. 다음 행동

### 13.1 completed

~~~text
검사가 완료되었습니다

┌─────────────────────────────────────────────┐
│ ⚠ 위험   78점                              │
│ 여러 위험 요소가 발견되었습니다.             │
└─────────────────────────────────────────────┘

판단 근거
[심각] APK 설치를 유도하는 표현
[주의] 공식 브랜드와 유사한 주소

권장 행동
1. 링크를 열거나 파일을 설치하지 마세요.
2. 공식 경로로 사실을 확인하세요.

문자 검사 · 검사 시각 · rules-v0.1.0

[다시 검사] [다른 검사] [관련 사례] [퀴즈]
~~~

safe이며 findings가 비어 있으면 빈 근거 카드를 만들지 않는다. 검사 범위에서 신호가 없었으며 안전을 보장하지 않는다는 설명을 표시한다.

### 13.2 partial

~~~text
┌─────────────────────────────────────────────┐
│ 일부 항목을 분석하지 못했습니다.              │
│ 완료된 결과만 표시합니다.             [재시도]│
└─────────────────────────────────────────────┘
[완료된 분석 결과]
~~~

warnings를 점수보다 먼저 표시한다. 실패 항목은 0점이나 안전으로 표현하지 않는다. 재시도는 원래 입력이 메모리에 있을 때만 제공한다. 외부 평판이 처음부터 disabled인 경우 장애 문구를 표시하지 않는다.

### 13.3 not_applicable QR

~~~text
QR 내용을 확인했습니다

이 QR은 HTTP(S) 주소가 아닙니다.
위험 점수와 등급은 제공하지 않습니다.

추출 내용
┌─────────────────────────────────────────────┐
│ WIFI:T:WPA;S:example;...                    │
└─────────────────────────────────────────────┘

[다른 QR 검사] [QR 안전수칙 보기]
~~~

점수·등급·finding을 렌더링하지 않는다. 추출 내용은 일반 텍스트로 표시하고 클릭·자동 실행하지 않는다.

### 13.4 데이터 없음과 등급 상향

직접 접근·새로고침 시 “표시할 검사 결과가 없습니다”와 세 검사 버튼을 제공한다.

overridden=true이면 다음 문구와 critical finding을 표시한다.

> 중대한 위험 요소가 확인되어 최종 등급이 위험으로 조정되었습니다.

내부 rule ID는 노출하지 않는다.

검사 결과 API에는 교육 사례 ID가 없으므로 MVP의 ‘관련 사례’ 버튼은 `/education` 목록으로 이동한다. 개별 사례 추천은 추가 계약 없이 추정하지 않는다. 퀴즈 결과만 채점 응답의 `related_case_id`로 상세 사례에 연결한다.

### 13.5 유형별 상세

- URL: hostname, scheme, 정규화 URL
- 문자: 위험 구간, URL별 성공·부분·실패, 생략 URL 수
- QR URL: 추출 텍스트, 정규화 URL, 이미지 해상도
- 모든 URL과 QR 텍스트는 클릭 불가능하게 표시한다.

스미싱 사례로 배우기

- 429에는 잠시 후 수동 재시도를 안내한다.

교육 조회와 퀴즈 조회·채점 요청은 FE 10초 제한을 적용한다. 실패 시 교육 화면은 재시도, 퀴즈 채점은 답안 유지 후 수동 재제출을 제공한다.

## 16. S-203 퀴즈

- **경로:** /quiz
- **조회:** GET /api/v1/quizzes/current
- **채점:** POST /api/v1/quizzes/grade
- **문제:** 10개
- **저장:** 현재 페이지 메모리

~~~text
문제 3 / 10
[■■■□□□□□□□]

다음 중 가장 안전한 행동은 무엇인가요?

( ) 문자 속 링크를 바로 연다
(●) 공식 앱에서 직접 확인한다
( ) 발신번호로 다시 전화한다

[이전]                                  [다음]
~~~

- 문제는 fieldset과 legend, 선택지는 라디오로 구현한다.
- 문제 풀이 중 정답을 공개하지 않는다.
- 이전 문제에서 답을 바꿀 수 있다.
- 미선택 상태에서 다음을 누르면 문제 영역에 오류와 포커스를 제공한다.
- 마지막 버튼은 “최종 제출”이다.
- 제출 전에 10문제 제출 확인 대화상자를 표시한다.
- 채점 중 답안과 이동을 비활성화한다.
- 조회 실패는 재시도, 채점 실패는 답안을 유지한 재제출을 제공한다.
- 409 버전 만료 시 새 퀴즈 시작을 안내한다.
- 답변이 하나 이상 있으면 페이지 이탈 확인을 제공한다.

정답·오답은 색상과 badge 문구를 함께 표시한다. 각 문제에 선택 답, 정답, 해설을 제공하고 related_case_id가 있으면 공개 사례 링크를 표시한다. 데이터가 없으면 퀴즈 시작을 안내한다.

## 18. 오류 처리

| 상태 | 사용자 표시 | 다음 행동 |
|---|---|---|
| 400/422 | 입력 가까이에 구체적 오류 | 입력 수정 |
| 404 | 사례·퀴즈가 없음 | 목록·메인 이동 |
| 409 | 퀴즈 버전 만료 | 새 퀴즈 시작 |
| 413/415 | 파일 조건 오류 | 파일 교체 |
| 429 | 요청이 많음 | 잠시 후 수동 재시도 |
| 500 | 처리 중 오류 | 입력 유지 후 재시도 |
| 503 | 일시 이용 불가 | 수동 재시도 |
| 504 | 분석 시간 초과 | 입력 유지 후 재시도 |
| 네트워크 | 연결 확인 | 입력 유지 후 재시도 |
| 비JSON 응답 | 일반 오류 | 재시도 |

request_id는 상세 정보나 문의용 영역에서 제공할 수 있다. 스택 트레이스, DB 오류, 내부 경로와 enum은 노출하지 않는다. POST 요청을 자동 재시도하지 않는다.

## 19. 사용자 문구

- 안전: “현재 검사 범위에서 뚜렷한 위험 신호가 발견되지 않았습니다.”
- 주의: “확인이 필요한 의심 요소가 발견되었습니다.”
- 위험: “중대한 위험 요소가 발견되었습니다. 아래 대응 방법을 확인하세요.”
- 분석 대상 아님: “QR은 인식했지만 HTTP(S) 주소가 아니어서 위험도 분석 대상이 아닙니다.”
- 참고 안내: “이 결과는 입력한 문자와 URL의 특징을 바탕으로 한 참고 정보입니다. 위험 요소가 발견되지 않아도 안전을 보장하지 않습니다.”

금지 문구:

- “100% 안전합니다.”
- “스미싱이 확실합니다.”
- “AI가 정확하게 판별했습니다.”
- 확인하지 않은 “사이트 내부를 검사했습니다.”

## 20. 접근성

- 모든 입력에 보이는 label을 제공한다.
- 키보드만으로 메뉴, 검사, 파일 선택, 퀴즈와 대화상자를 사용할 수 있어야 한다.
- 포커스 표시를 제거하지 않는다.
- 오류와 상태는 색상 외에 문구와 아이콘으로 표시한다.
- 상태 변경은 aria-live로 알리되 반복 안내를 줄인다.
- heading 순서를 지킨다.
- 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 대화상자는 포커스 이동·가두기·복귀와 Escape 닫기를 지원한다.
- 이미지 미리보기 alt는 용도를 설명한다.
- 애니메이션 감소 설정을 존중한다.
- 200% 확대에서도 핵심 작업이 잘리지 않아야 한다.

## 21. 보안·개인정보 UI

- URL과 QR 데이터는 anchor로 만들지 않는다.
- 사용자 입력을 HTML로 직접 출력하지 않는다.
- 문자 강조는 안전한 텍스트 분할로 구현한다.
- 파일명을 HTML로 해석하지 않는다.
- 원문을 analytics·오류 추적 이벤트에 보내지 않는다.
- 결과·답안을 localStorage에 저장하지 않는다.
- 뒤로가기·새로고침으로 POST를 재전송하지 않는다.
- 개인정보 제거 안내와 저장 범위를 검사 전에 표시한다.

## 22. 상태 모델

검사:

~~~text

→ success(completed | partial | not_applicable)
→ failure(validation | network | server | timeout | rate_limit)
~~~

교육:

## 25. 2차 회원·기관 UI 확장 계획

2차 기능은 MVP 화면 구현을 지연시키지 않도록 별도 경로와 권한 영역으로 설계한다.

~~~text
/login                         로그인·기관 초대 수락
/mypage/learning               개인 학습 기록
/mypage/saved-results          선택 저장한 결과 요약
/organization                  기관 관리자 홈
/organization/members          구성원·초대 관리
/organization/assignments      교육 배정·이수 관리
/organization/analytics        익명화된 학습 통계
/organization/content          기관 전용 콘텐츠
~~~

- **개인 회원:** 학습 기록과 저장한 결과 요약을 직접 조회·삭제한다.
- **기관 학습자:** 배정된 교육, 마감일, 진행률과 이수 상태를 확인한다.
- **기관 관리자:** 구성원 초대, 교육 배정, 이수율과 익명 통계를 확인한다.
- 메뉴 노출은 역할에 따라 달라지지만 실제 권한은 서버가 검증한다.
- 기관 화면에는 구성원의 검사 문자 원문, 전체 URL, QR 이미지와 개인별 검사 내역을 표시하지 않는다.
- 소규모 집단 통계는 숨기고 개인을 비교하거나 낙인찍는 순위 UI를 만들지 않는다.
- 요금제·결제 화면은 사업 모델 검증 후 별도 설계하며 2차 기본 범위에도 포함하지 않는다.

2차 기관 관리자는 자기 기관에 배정된 교육의 구성원별 이수 상태를 확인한다. 점수·오답 유형의 분석은 최소 집계 인원을 충족하는 통계로 제공하며, 개인 검사 원문·개별 URL·선택 저장 요약에는 접근하지 않는다. 집계 기준과 보관·삭제 정책은 2차 상세 설계에서 확정한다.

# 스미싱 예방 교육 및 탐지 시스템 기능 명세서

- **문서 버전:** Draft v0.6
- **작성일:** 2026-10-11
- **검토 상태:** 팀 합의 전 제안안
- **MVP 목표:** 사용자가 URL, 문자 메시지 또는 QR 코드를 제출하면 규칙 기반으로 위험 요소를 분석하고, 판정 근거와 대응 방법을 제공한다.

## 1. 문서 개요

### 1.1 목적

본 문서는 사용자가 웹에서 의심스러운 URL, 문자 메시지, QR 코드 및 이미지를 제출하면 위험 요소를 분석하고 예방 정보를 제공하는 **스미싱 예방 교육 및 탐지 시스템**의 기능 요구사항을 정의한다.

### 1.2 서비스 목표

- 사용자가 의심 자료를 쉽고 빠르게 검사할 수 있도록 한다.
- 단순 판정이 아니라 위험도와 판단 근거를 함께 제공한다.
- 검사 결과에 맞는 행동 요령과 예방 교육을 제공한다.
- 개인정보와 업로드 자료를 최소한으로 수집·보관한다.

### 1.3 판정 원칙

- 분석 결과는 수사기관 또는 보안 전문기관의 확정 판정이 아닌 참고 정보로 제공한다.
- 위험 평가가 수행된 결과는 `안전`, `주의`, `위험`과 0~100점으로 표현한다. 비URL QR은 `not_applicable`, `risk=null`로 반환하며 점수와 등급을 표시하지 않는다.
- 사용자가 결과를 이해할 수 있도록 탐지 근거와 권장 행동을 함께 표시한다.

### 1.4 위험 등급 기준

| 점수 | 등급 | 의미 |
|---:|---|---|
| 0~29 | 안전 | 현재 분석 범위에서 뚜렷한 위험 요소가 발견되지 않음 |
| 30~59 | 주의 | 하나 이상의 의심 요소가 발견되어 추가 확인이 필요함 |
| 60~100 | 위험 | 다수의 위험 요소 또는 중대한 위험 요소가 발견됨 |

다음 치명 규칙이 확인되면 합산 점수가 60점 미만이어도 최종 등급을 `위험`으로 상향할 수 있다.

- 알려진 악성 URL 또는 악성 도메인 목록과 일치
- APK 또는 실행 파일 설치를 직접 유도
- 비밀번호, 인증번호, 카드번호 등 중요 인증정보 탈취를 명확하게 유도
- 공식 기관 또는 브랜드를 사칭하면서 비공식 도메인에서 로그인을 요구

판정 시 다음 원칙을 적용한다.

- 점수 계산 결과와 최종 등급을 별도 값으로 관리한다.
- 치명 규칙으로 등급이 상향된 경우 결과 화면에 해당 근거를 표시한다.
- HTTPS 미사용 등 하나의 약한 신호만으로 `위험` 등급을 부여하지 않는다.
- `안전`은 위험 요소가 발견되지 않았다는 의미이며 대상의 절대적인 안전을 보장하지 않는다.
- 규칙별 배점과 치명 규칙 목록은 테스트 결과에 따라 조정하고 변경 이력을 관리한다.

### 1.5 개발 기준과 데이터 저장 결정

- **사용자 확정:** MVP부터 OCI 서버의 Docker PostgreSQL을 사용한다.
- **PM 설계안:** DB 저장 대상은 교육 사례·예방수칙·퀴즈 문제·선택지·정답·해설이다. BE API로 조회하고 채점한다.
- 탐지 규칙은 BE 버전 관리 파일을 유지한다. 검사 원문·이미지·개인 검사 이력·퀴즈 제출 기록은 DB에 저장하지 않는다.
- 입력 경계와 응답 형식의 기준 문서는 `05_API_Specification.md`, 데이터 구조는 `04_Database_Design.md`다.
- 점수 구간·규칙 배점·집계 방식은 팀 검토 및 평가 데이터 검증 전 초안이다. 점수는 악성 확률이 아니다.
- 각 분석 단위는 규칙 배점 합산 후 100점으로 제한한다. 문자는 문자 패턴 점수와 성공한 URL 점수의 최댓값을 사용하고 치명 규칙은 합집합으로 반영한다.
- 단순 APK 언급이나 정상 로그인 안내만으로 치명 규칙을 적용하지 않는다.

## 2. 사용자 유형

| 사용자 | 설명 | 주요 권한 |
|---|---|---|
| 비회원 | 로그인하지 않은 일반 사용자 | 기본 검사, 결과 확인, 공개 교육 콘텐츠와 퀴즈 이용 |
| 개인 회원 | 계정을 보유한 일반 사용자 | 학습 기록, 사용자가 선택해 저장한 결과 요약, 맞춤 교육 이용 |
| 기관 학습자 | 학교·기업·공공기관에 초대된 사용자 | 배정된 교육 이수, 퀴즈 응시, 본인 진도 확인 |
| 기관 관리자 | 기관 교육 담당자 | 구성원·교육 배정 관리, 익명화된 이수·학습 통계 확인 |
| 서비스 운영자 | 서비스 운영 담당자 | 교육 콘텐츠, 퀴즈, 탐지 규칙 및 전체 운영 통계 관리 |

> 기본 검사와 공개 교육은 로그인 없이 제공한다. 개인 회원과 기관 기능은 핵심 탐지 기능 완성 후 개발하는 2차 범위이며, 로그인 때문에 기본 검사 접근성이 낮아져서는 안 된다.

### 2.1 서비스 제공 및 수익 구조

- **대국민 무료 서비스:** 비회원 검사, 결과 설명, 공개 사례 학습과 기본 퀴즈를 무료로 제공한다.
- **개인 회원 확장:** 학습 기록과 선택 저장 기능을 제공한다. 무료·유료 경계는 사용자 검증 후 결정한다.
- **기관용 교육 SaaS:** 학교·기업·공공기관이 구성원을 초대하고 교육을 배정하며, 이수 현황과 익명화된 통계를 확인하는 구독형 서비스를 핵심 수익 모델로 검토한다.
- **검사 API 제공:** 충분한 정확도와 운영 안정성을 확보한 뒤 사용량 기반 API 제공을 후속 수익 모델로 검토한다.
- **맞춤 구축·운영 지원:** 기관별 교육 콘텐츠, 정책 문구, 배포·운영 지원을 별도 계약 항목으로 검토한다.

캡스톤 MVP는 무료 공개 서비스의 핵심 가치를 검증하는 데 집중한다. 실제 결제, 요금제, 청구 기능은 MVP에 포함하지 않으며 기관용 기능은 시연 가능한 2차 설계로 정의한다.

## 3. 기능 우선순위

| 구분 | 의미 |
|---|---|
| Must | MVP에 반드시 포함해야 하는 기능 |
| Should | 핵심 기능 완성 후 우선적으로 추가할 기능 |
| Could | 일정과 인력이 허용될 때 추가할 기능 |

기능별 개발 단계는 다음과 같이 구분한다.

| 개발 단계 | 의미 |
|---|---|
| MVP | 1차 배포와 최종 시연을 위해 반드시 완성할 범위 |
| 2차 | MVP 안정화 후 개발할 확장 범위 |
| 도전 | 일정, 데이터 및 기술 검증 결과에 따라 착수할 범위 |

우선순위는 기능의 중요도를, 개발 단계는 실제 구현 시점을 의미한다. 팀 회의에서 범위가 승인되기 전까지 본 문서의 개발 단계는 제안안으로 취급한다.

## 4. 기본 웹사이트 기능

### F-001 메인 화면

- **목적:** 서비스의 용도와 핵심 검사 기능을 안내하고 사용자가 검사 화면에 빠르게 접근하도록 한다.
- **사용자:** 모든 사용자
- **우선순위:** Must
- **개발 단계:** MVP
- **주요 내용:**
  - 서비스 소개 및 사용 방법
  - URL, 문자, QR 코드 검사 바로가기
  - 2차 개발 시 이미지 OCR 검사 바로가기 추가
  - 대표적인 스미싱 유형과 예방수칙
  - 분석 결과가 참고용이라는 안내
- **완료 조건:** 사용자가 메인 화면에서 각 검사 기능으로 이동할 수 있고 서비스의 목적과 주의사항을 확인할 수 있다.

### F-002 검사 유형 선택

- **목적:** 사용자가 제출할 자료 유형에 맞는 검사 화면을 제공한다.
- **사용자:** 모든 사용자
- **우선순위:** Must
- **개발 단계:** MVP
- **MVP 지원 유형:** URL, 문자 메시지, QR 코드 이미지
- **2차 지원 유형:** 문자·웹페이지 캡처 이미지
- **기본 흐름:**
  1. 사용자가 검사 유형을 선택한다.
  2. 시스템이 해당 유형의 입력 화면과 안내를 표시한다.
  3. 사용자가 데이터를 입력하거나 파일을 업로드한다.
- **완료 조건:** 각 유형에 적합한 입력 방법과 허용 범위가 명확하게 표시된다.

### F-003 공통 입력 검증

- **목적:** 잘못된 입력과 위험한 파일이 분석 시스템에 전달되는 것을 방지한다.
- **우선순위:** Must
- **개발 단계:** MVP
- **검증 항목:**
  - 빈 입력 및 공백 입력 방지
  - URL 형식과 허용 프로토콜 검사
  - 문자 길이 제한
  - 이미지 확장자, MIME 타입 및 용량 제한
  - 지원하지 않는 파일 차단
  - 중복 제출 및 과도한 요청 제한
- **예외 처리:** 검증 실패 시 문제 원인과 수정 방법을 입력 항목 가까이에 표시한다.
- **완료 조건:** 유효하지 않은 입력은 분석 요청으로 전송되지 않으며 사용자가 원인을 알 수 있다.

### F-004 공통 검사 결과 화면

- **목적:** 모든 검사 결과를 일관된 형식으로 제공한다.
- **우선순위:** Must
- **개발 단계:** MVP
- **출력:**
  - 종합 위험 등급: 안전 / 주의 / 위험
  - 위험 점수: 0~100점
  - 치명 규칙에 의한 등급 상향 여부
  - 탐지된 위험 요소와 판단 근거
  - 사용자 권장 행동
  - 검사 시각
  - 참고용 결과 및 오탐 가능성 안내
  - 다시 검사하기
- **예외 처리:** 일부 분석 모듈이 실패한 경우 성공한 항목의 결과와 실패 항목을 구분하여 보여준다.
- **완료 조건:** 사용자가 판정 결과, 판정 이유, 이후 행동 방법을 한 화면에서 확인할 수 있다.

## 5. 스미싱 탐지 기능

### F-101 URL 위험도 분석

- **목적:** 사용자가 입력한 URL의 구조와 알려진 위험 정보를 분석한다.
- **사용자:** 모든 사용자
- **우선순위:** Must
- **개발 단계:** MVP
- **입력:** 앞뒤 공백 제거 후 최대 2,048 code point인 절대 HTTP 또는 HTTPS URL 1개. 직접 사이트 접속·DNS 조회·단축 링크 확장은 하지 않는다.
- **분석 항목:**
  - HTTPS 사용 여부
  - IP 주소 직접 사용 여부
  - 단축 URL 여부
  - 과도하게 긴 URL 또는 비정상적인 인코딩
  - 특수문자 및 유사 문자 사용
  - 과도하거나 오해를 유발하는 하위 도메인
  - 공식 브랜드 도메인과 유사한 위조 도메인
  - 로그인, 결제, 인증정보 입력을 유도하는 경로
  - APK 또는 실행 파일 다운로드 유도
  - 알려진 악성 URL 또는 도메인 목록과의 일치 여부
- **외부 연동 원칙:** 외부 악성 URL 평판 조회는 내부 규칙 분석을 보완하는 선택 기능으로 사용하며 MVP 완료 조건에 포함하지 않는다.
- **기본 흐름:**
  1. 사용자가 URL을 입력하고 검사를 요청한다.
  2. 시스템이 URL 형식을 검증하고 정규화한다.
  3. URL 문자열과 도메인을 분석한다.
  4. 각 규칙의 결과를 종합해 위험 점수를 계산한다.
  5. 위험 등급, 근거, 권장 행동을 표시한다.
- **예외 처리:** 접속 불가 또는 외부 평판 서비스 실패 시 문자열 기반 분석 결과를 우선 제공한다.
- **완료 조건:** 입력된 URL에 대한 등급·점수·판정 요약이 표시된다. 탐지 신호가 없으면 검사 범위와 한계를 설명하고 위험 항목은 빈 배열로 제공한다.

### F-102 문자 메시지 분석

- **목적:** 문자 또는 메신저 내용을 분석해 스미싱 가능성을 판단한다.
- **사용자:** 모든 사용자
- **우선순위:** Must
- **개발 단계:** MVP
- **입력:** 사용자가 붙여넣은 문자 메시지
- **입력 제한:** 공백을 포함해 최대 5,000 Unicode code point
- **분석 항목:**
  - URL 및 전화번호 포함 여부
  - APK 설치 또는 앱 다운로드 유도
  - 긴급성, 공포, 혜택을 강조하는 표현
  - 결제, 송금, 대출 및 투자 유도
  - 개인정보, 카드번호, 비밀번호 및 인증번호 요구
  - 공공기관, 금융기관, 택배사 및 지인 사칭 표현
  - 청첩장, 부고장, 범칙금, 단체예약 등의 대표 유형
- **기본 흐름:**
  1. 사용자가 문자 내용을 입력한다.
  2. 시스템이 위험 키워드와 문장 패턴을 분석한다.
  3. 명시적 HTTP(S) URL을 추출하고 중복 제거 후 앞의 최대 5개에 F-101 분석을 수행한다. 초과 항목은 생략하고 부분 결과 경고를 제공한다.
  4. 분석 결과와 주의해야 할 문구를 강조해 표시한다.
- **예외 처리:** URL 분석이 실패해도 문자 내용 분석 결과는 제공한다.
- **입력 처리:** 화면에서 현재 글자 수를 실시간으로 표시하며 5,000자를 초과하면 분석 요청을 차단한다.
- **완료 조건:** 위험 등급, 근거, 탐지된 URL과 위험 문구가 구분되어 표시된다.

### F-103 QR 코드 분석

- **목적:** 이미지 속 QR 데이터를 추출하고 포함된 URL의 위험도를 분석한다.
- **사용자:** 모든 사용자
- **우선순위:** Must
- **개발 단계:** MVP
- **입력:** QR 코드가 포함된 PNG, JPG 또는 JPEG 이미지 파일
- **입력 제한:** 파일 1개, 최대 10,000,000 bytes(10MB), 가로·세로 각각 최대 4,096픽셀. 복수 QR은 거부한다.
- **제외 형식:** SVG, PDF, HEIC 및 애니메이션 이미지
- **기본 흐름:**
  1. 사용자가 QR 이미지를 업로드한다.
  2. 시스템이 이미지에서 QR 코드를 탐지한다.
  3. QR 내부 데이터를 추출한다.
  4. 데이터가 URL이면 F-101 분석을 수행한다.
  5. 추출 결과, 위험도 및 접속 주의사항을 표시한다.
- **예외 처리:** QR을 인식하지 못하면 밝기, 초점, 촬영 각도 등의 재촬영 방법을 안내한다.
- **파일 처리:** 확장자와 실제 MIME 타입을 모두 검증하며 정상 분석 완료 후 즉시 삭제한다. 실패 또는 중단으로 즉시 삭제하지 못한 임시 파일도 업로드 후 10분 이내 삭제한다.
- **완료 조건:** QR 데이터를 사용자가 직접 링크를 열지 않고 확인할 수 있으며 URL인 경우 위험 분석 결과가 표시된다.

### F-104 이미지 OCR 분석

- **목적:** 문자 메시지 또는 의심 화면 캡처에서 텍스트와 URL을 추출해 분석한다.
- **사용자:** 모든 사용자
- **우선순위:** Should
- **개발 단계:** 2차
- **입력:** 문자 또는 웹 화면이 포함된 이미지
- **기본 흐름:**
  1. 사용자가 이미지를 업로드한다.
  2. 시스템이 OCR로 텍스트와 URL을 추출한다.
  3. 추출된 텍스트는 F-102, URL은 F-101로 분석한다.
  4. 추출 내용과 종합 결과를 표시한다.
- **예외 처리:** 인식률이 낮으면 원본에 가까운 선명한 이미지를 다시 올리도록 안내한다.
- **완료 조건:** 추출된 텍스트를 사용자가 확인·수정할 수 있고 수정된 내용으로 재분석할 수 있다.

### F-105 가짜 로그인 페이지 분석

- **목적:** 브랜드를 사칭하거나 개인정보 입력을 유도하는 웹페이지의 위험 요소를 분석한다.
- **사용자:** 모든 사용자
- **우선순위:** Could
- **개발 단계:** 도전
- **분석 항목:**
  - 브랜드 공식 도메인과 실제 도메인의 일치 여부
  - 비밀번호, 카드번호, 인증번호 입력 폼 존재 여부
  - 외부 도메인으로 제출되는 폼
  - APK 및 실행 파일 다운로드 유도
  - 화면에 표시된 브랜드와 도메인의 불일치
- **보안 조건:** 서버가 의심 사이트에 직접 접속해야 하는 분석은 격리된 환경에서만 수행한다.
- **대체 흐름:** 격리 환경이 없으면 URL 문자열과 사용자가 업로드한 화면 캡처만 분석한다.
- **완료 조건:** 분석 범위와 한계를 명확히 표시하며 탐지된 위험 요소를 사용자에게 설명한다.

### F-106 조작 이미지 판별

- **목적:** 업로드 이미지의 편집 또는 조작 가능성을 참고 정보로 제공한다.
- **우선순위:** Could
- **개발 단계:** 도전
- **제한 사항:** 데이터셋과 모델 정확도 확보가 어려우므로 MVP 범위에서 제외한다.
- **표시 원칙:** 조작 여부를 확정적으로 표현하지 않고 가능성과 근거를 제공한다.

## 6. 예방 교육 기능

### F-201 스미싱 사례 학습

- **목적:** 대표 사례를 통해 사용자가 스미싱 특징과 대응법을 학습하도록 한다.
- **우선순위:** Must
- **개발 단계:** MVP
- **사례 유형:** 택배, 청첩장·부고장, 공공기관·범칙금, 금융기관·대출, 투자 리딩방, 가족·지인, APK 설치 유도
- **데이터 제공:** PostgreSQL의 공개 교육 사례와 예방수칙을 BE 조회 API로 제공한다. 관리자 편집 화면은 MVP에 포함하지 않는다.
- **MVP 콘텐츠 수:** 대표 유형 7개 이상, 유형별 사례 1개 이상
- **콘텐츠 구성:** 예시 메시지, 의심 지점, 피해 과정, 올바른 대응 방법
- **완료 조건:** 유형별 사례 목록과 상세 교육 내용을 조회할 수 있다.

### F-202 예방수칙 및 피해 대응 안내

- **목적:** 스미싱 예방과 피해 발생 후 대응 절차를 안내한다.
- **우선순위:** Must
- **개발 단계:** MVP
- **주요 내용:**
  - 의심 URL과 APK 설치 예방 방법
  - 공식 앱과 공식 홈페이지 확인 방법
  - 계정 및 금융정보 보호 방법
  - 비밀번호 변경과 금융기관 연락 절차
  - 경찰청 등 신고·상담 기관 안내
- **완료 조건:** 검사 결과 화면과 교육 화면에서 상황에 맞는 대응 정보를 확인할 수 있다.

### F-203 교육 퀴즈

- **목적:** 사용자가 학습 내용을 점검하고 스미싱 식별 능력을 기르도록 한다.
- **우선순위:** Must
- **개발 단계:** MVP
- **데이터 제공:** DB의 버전별 문제를 BE에서 조회하고 정답은 최종 제출 후 채점 응답으로 제공한다. 제출 기록은 저장하지 않는다.
- **MVP 문제 수:** 총 10문제
- **기능:** 객관식·OX 문제, 최종 제출 후 정답 확인, 문제별 해설, 최종 점수, 오답 복습
- **완료 조건:** 로그인하지 않은 사용자도 퀴즈를 완료하고 점수와 해설을 확인할 수 있다.

- **개발 단계:** 2차

## 10. 비기능 요구사항

### NFR-001 보안 및 개인정보 보호

- 업로드 파일의 확장자, MIME 타입 및 크기를 검증한다.
- 업로드 파일을 실행하지 않으며 저장 파일명은 예측할 수 없도록 생성한다.
- 업로드 파일과 임시 분석 데이터는 검사 완료 후 정해진 시간 안에 삭제한다.
- 문자 원문, 이미지 및 개인정보는 서비스 제공에 필요한 최소 범위만 처리한다.
- 관리자와 일반 사용자의 접근 권한을 분리한다.
- 요청 횟수 제한과 입력값 정제를 적용한다.
- 의심 URL에 직접 접속하는 분석은 격리된 환경에서만 수행한다.

### NFR-002 성능 및 안정성

- URL과 문자 분석은 일반적인 환경에서 사용자가 기다릴 수 있는 시간 안에 완료한다.
- 이미지 분석 중에는 진행 상태를 표시한다.
- 일정 시간을 초과한 분석은 종료하고 재시도 방법을 안내한다.
- 외부 분석 서비스 장애 시 가능한 내부 분석 결과를 부분 제공한다.

### NFR-003 접근성과 사용성

- 모바일, 태블릿 및 데스크톱 화면을 지원한다.
- 위험도를 색상만으로 구분하지 않고 아이콘과 텍스트를 함께 사용한다.
- 보안 용어에는 쉬운 설명을 제공한다.
- 오류 메시지에는 원인과 사용자가 취할 수 있는 행동을 포함한다.

### NFR-004 결과 신뢰성

- 모든 판정에 가능한 범위에서 근거를 제공한다.
- 검사 시각과 적용된 분석 버전을 기록한다.
- 확정 판정이 아닌 참고용 결과임을 명확히 표시한다.
- 탐지 규칙과 점수 기준은 테스트 가능한 형태로 관리한다.

## 11. 개발 범위

### 11.1 MVP 정의

MVP는 **URL·문자·QR 검사 → 위험 점수와 근거 제공 → 대응 방법 및 예방 교육 연결**의 전체 사용자 흐름을 배포 환경에서 시연할 수 있는 상태를 의미한다.

탐지는 자체 AI 모델 학습이 아닌 규칙 기반 점수 계산을 기본으로 한다. 외부 악성 URL 평판 서비스는 선택적으로 연동하되, 외부 서비스가 없어도 기본 분석이 동작해야 한다.

### 11.2 MVP 포함 범위

- F-001 메인 화면
- F-002 검사 유형 선택
- F-003 공통 입력 검증

### 11.6 MVP 완료 조건

- URL, 문자 메시지, QR 코드의 세 가지 입력 유형을 검사할 수 있다.
- 잘못된 입력, QR 인식 실패, 분석 시간 초과 등 주요 예외 상황을 처리한다.
- 평가된 결과에 위험 등급·점수·판정 요약·권장 행동을 표시한다. 위험 신호가 없으면 findings는 빈 배열로 두고 검사 범위를 설명한다. 비URL QR은 분석 대상 아님을 표시한다.
- 문자와 QR에서 URL이 추출되면 F-101 URL 분석으로 연계한다.
- 업로드한 QR 이미지는 분석 후 정해진 보관 시간 안에 삭제한다.
- 외부 분석 서비스가 실패해도 가능한 내부 분석 결과를 제공한다.
- 모바일과 데스크톱 환경에서 핵심 사용자 흐름을 완료할 수 있다.
- 기능별 정상·주의·위험·오류 테스트 사례가 문서화되어 있다.
- 실제 배포 환경에서 메인 화면부터 결과와 교육 콘텐츠까지 전체 흐름을 시연할 수 있다.

## 12. 공통 완료 기준

모든 기능은 다음 조건을 만족해야 완료된 것으로 판단한다.

- 정상 흐름과 주요 예외 흐름이 구현되어 있다.
- 입력 검증과 오류 안내가 제공된다.
- 모바일과 데스크톱 환경에서 핵심 기능을 이용할 수 있다.
- 기능별 테스트가 작성되거나 테스트 결과가 문서화되어 있다.
- 개인정보와 업로드 데이터 처리 방식이 명세와 일치한다.
- 분석 결과 화면에는 판정 요약과 사용자 행동 지침이 표시된다. 비URL QR은 점수 없이 범위 안내를 표시한다. 교육·퀴즈에는 해당 기능별 완료 기준을 적용한다.
